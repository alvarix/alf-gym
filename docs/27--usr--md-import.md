## Scope decision

v0 imports `.md` workout files as **draft Workouts only** (Workout → Day → Block → Prescription). No sessions, no actuals, no per-side sets, no merge-into-existing. **Template-only forever** — session-side parsing is not on the roadmap. The 9.2B sample is the canonical first fixture.

## Notation decisions locked

These must also be applied to `docs/4-notation.md`:

- `!` is now a **mandatory load terminator** (no longer means "notable")
- `:` before `!` = pair of implements (`:20!` = two 20lb DBs)
- `:` after `!` (or standalone) = per-side reps (`40!:5-3`, `:5-3`)
- `;` is unused
- "Notable" status is dropped from syntax — if surfaced, it's a UI-derived signal from history, not a typed token

## Canonical-MD changes proposed (reliability)

The 9.2B sample needs ~10 source edits before it parses cleanly. Full table is in the LLM spec, section *"Grammar deviations in the 9.2B sample"*. The big ones:

- [ ] Settle on `*Name*` (single asterisks). Replace all `**Name**`. Close any unclosed `**`.
- [ ] No bullets directly under `#` — every prescription lives under a `## N. <Block>` heading. Wrap the orphan "Shoulder PT" bullets in `## 0. Shoulder PT`.
- [ ] Move trailing-after-` - ` text on the title line onto an indented next line.
- [ ] Per-line: drop the leading `:` on `:N` tokens that were meant bilaterally → `N`. Keep `:N` only where genuinely per-side (after `!` if there's a load).
- [ ] Add mandatory `!` to every load value (`40` → `40!`, `:20` → `:20!`, `^15` → `^15!`).
- [ ] Replace `.8-2` (leading dot) with `8-2`.
- [ ] Un-indent supplementary `- [ ]` drills (e.g. *Glute Amnesia Drills*, *Eyes closed balance*) to be siblings in the block, not nested under another prescription.
- [ ] Normalize `alt:` → `Alt:`, `cue:` → `Cue:` casing.
- [ ] Move the "Substitution guide for future KB swaps:" prose under `### Notes` at the end of its block, or delete.
- [ ] Leave one blank line between a block's prose description and its first `- [ ]` bullet.

These would go in `docs/import-massage.md` as a runnable recipe list.

## Feedback (implementation notes)

- Notation parsing is **inline in `parser.js`** rather than reusing `fieldsFromToken` from app.js. Reason: the old in-app parser treats `!` as a "notable" flag, while v4 treats `!` as a load terminator. Reusing it would have required either a runtime mode flag or a destructive rewrite of the en/syn editing path. The import parser is small enough (~80 LOC) that duplication beats coupling here.
- The `name` field is stored on each prescription record alongside `exerciseId: null`. The block-view edit form was updated to pre-fill `exerciseQuery` from `p.name` when `exerciseId` is null, so the user can map imported exercises to canonical Exercise rows with one click in the omnibox.
- Encountered one IDB structured-clone issue (Alpine reactive proxy can't be cloned, same shape as the JSON-import postmortem). Fix: `JSON.parse(JSON.stringify(this.mdImportPreview))` before opening the Dexie transaction.
- The fixture file is **synthetic** — the user's raw 9.2B vault file was not available in this session. The fixture covers all 13 grammar deviations called out in the LLM spec.
- Notation tokens must be contiguous (no spaces). `:20! 20-3` (with space) → notes; `:20!20-3` → parsed. This matches the spec but should be re-tested against a real vault file.
